# ADR-007: CloudFront VPC Originsの採用

- **日付**: 2026-10-20
- **ステータス**: Accepted
- **対象**: Phase 4 / AWS Infrastructure

## 背景

座席予約システムをAWSへデプロイするにあたり、CloudFrontを公開入口とし、Spring Boot APIをECS/Fargateで稼働させる。

Backendへの通信経路として、Public ALBをオリジンとする方式と、CloudFront VPC Origins経由でInternal ALBを使用する方式を比較した。

## 決定

**CloudFront VPC Originsを採用し、CloudFrontを唯一の公開入口とする。**

```text
Browser
    |
    v
CloudFront（公開）
    |
    +-- S3（非公開 / OAC）
    |     React静的ファイル
    |
    +-- VPC Origins
            |
            v
        Internal ALB
            |
            v
        ECS/Fargate
            |
            v
        RDS PostgreSQL
```

- ALB、ECS、RDSをPrivate Subnetに配置し、ALBへの通信元はCloudFront VPC Origins、ECSはALB、RDSはECSに限定する。
- CloudFront → ALBはHTTPS:443、ALB → ECSはHTTP:8080とする。
- DNS・ACMは手動管理とし、Terraformへ公開／Origin用FQDNと既存証明書ARNを渡す。
- 認証・認可は引き続きCognitoとSpring Securityで実施する。

## 理由

- **公開範囲の最小化**：ALBを非公開にし、CloudFrontを迂回したBackendへの直接アクセスを防ぐ。
- **セキュリティ境界の明確化**：各レイヤーで通信元を限定し、アプリケーション認証とは独立したアクセス制御を行う。
- **アクセス制御の簡素化**：Public ALBで必要となるCloudFront送信元制限や専用ヘッダー検証への依存を減らす。

Public ALB＋CloudFrontも要件を満たし、構築・デバッグが比較的容易だが、ALB自体はインターネット向けとなる。今回は公開範囲を最小化できるVPC Originsを優先する。

## 影響・今後の拡張

- VPC Originの追加により、Terraformの構成・依存関係が増える。
- Internal ALBへ外部から直接アクセスできないため、障害調査にはCloudFront・ALBのログ等を使用し、公開APIの疎通はCloudFront経由で確認する。
- ECSからECR・CloudWatch Logs・Cognito等への外向き通信が必要。関連設計ではNAT Gateway 1台を採用した。
- VPC Endpointによる最適化、Cognito実認証E2EのCI化、WAF・追加のDDoS対策は本ADRの対象外とする。

ネットワークの詳細は[AWS設計](../system-design/aws-architecture.md)、デプロイ・ロールバックの管理分担は[CI/CD設計](../system-design/cicd-design.md)、State・構築・破棄の操作は[Terraform README](../../terraform/README.md)で管理する。

### 決定の経緯

VPC Originsの採用は維持し、実装時に通信設定と関連する運用方針を具体化した。CI/CDの変更経緯は以下に要約し、現在の詳細は関連設計を参照する。

| 日付 | 決定・変更 | 理由 |
| --- | --- | --- |
| 2026-10-20 | VPC Origins＋Internal ALBを採用 | CloudFrontを唯一の公開入口とするため |
| 2026-10-27 | HTTPS接続、DNS・ACMの手動管理、NAT Gatewayを具体化 | 採用構成を実装可能な設定へ落とし込むため |
| 2026-10-27 | CI/CDの自動化を成果物準備までに限定し、公開は手動とした | Terraformとの管理重複を避け、Build & Scrapの操作を単純化するため |
| 2026-10-28 | 初回手動公開・通常更新のみ自動化する案から、初回・更新共通のCDへ変更 | デプロイ操作を統一するため |
| 2026-10-28 | 各リリースをTerraformで登録する方式を見直し、基本定義はTerraform、リリース定義の登録・反映はCDに分担 | 任意実行のCDだけでデプロイを完結させるため |
