# ADR-003: APIエラーレスポンスの標準化

- **日付**: 2026-10-08
- **ステータス**: Accepted
- **対象**: Phase 1 / API設計

## 背景

APIのエラーレスポンスを統一するにあたり、独自DTOとSpring標準の`ProblemDetail`を比較した。

エラー形式の独自実装を最小限に抑え、標準的なHTTP APIの設計を採用したい。

## 決定

RFC 9457準拠のSpring `ProblemDetail`を採用する。

- エラーレスポンスの`Content-Type`は`application/problem+json`とする。
- `type`、`title`、`status`、`detail`、`instance`を共通フィールドとする。
- 独自の`code`フィールドはレスポンスに含めない。
- エラーの分類はHTTPステータスとAPIの組み合わせで行う。
- 例外からHTTPステータスへの変換は共通例外ハンドラーで行う。

## 理由

- **独自DTO**：レスポンス構造を自由に設計できるが、独自仕様の定義・保守が必要となる。
- **ProblemDetail（採用）**：RFC 9457に基づく共通形式を利用でき、Spring標準の例外処理と統合しやすい。
- **独自codeの追加**：現時点ではHTTPステータスで必要なエラーを区別できるため、追加しない。

## 影響・今後の拡張

- エラーの発生条件とHTTPステータスの対応関係はAPI定義で管理する。
- 内部のエラー分類や定数化は実装側で必要に応じて判断する。
- 同一HTTPステータス内で複数の業務エラーを識別する必要が生じた場合は、`type`の固有URIや独自フィールドによる拡張を検討する。
