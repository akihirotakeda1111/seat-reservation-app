# ADR-004: ローカル環境のCompose統合起動

- **日付**: 2026-10-12
- **ステータス**: Accepted
- **対象**: ローカル開発環境 / AWS配置への準備

## 背景

DBはCompose、APIと画面はホスト上で別々に起動していた。起動を一本化し、将来のS3 + CloudFront、ECS/Fargate、RDS構成へ移行できるようにする。

## 決定

- ルートのComposeでPostgreSQL・Spring Boot・Viteを起動する。
- DB・APIのヘルスチェックを使い、準備完了後に依存サービスを起動する。
- Spring Bootの `local` プロファイルと接続情報はComposeで指定する。
- APIは複数段階のDockerビルドでJARを作り、非rootユーザーで実行する。イメージには環境固有のプロファイルを固定しない。
- フロントは開発用コンテナでViteを起動し、ソースをマウントする。依存関係はイメージ内に置く。

## 影響・今後の拡張

- Javaの変更はイメージ再ビルドで反映する。ホスト上での個別起動も残す。
- AWSではフロントのビルド成果物をS3へ、APIイメージをECS/Fargateへ配置する。Composeはローカル専用とする。
- 本番用の認証実装、秘密情報、ヘルスチェック、ログ、CloudFrontの `/api/*` 転送はAWS対応時に追加する。
- コンテナビルドはテストを実行しない。Testcontainers等のテストはDockerに接続できるホストまたはCIで別途実行する。
