# ADR-002: Phase 1における仮ユーザー識別方式

- **日付**: 2026-10-08
- **ステータス**: Accepted
- **対象**: Phase 1 / ユーザー識別

## 背景

Phase 1では予約・キャンセルの基本機能を優先し、認証認可の本格的な実装はPhase 3で行う。

一方、ユーザーごとの予約状態表示と所有者判定には、操作ユーザーの識別が必要となる。

## 決定

ローカル環境限定で、`X-Demo-User`ヘッダーによる仮ユーザー識別を採用する。

- `demo-user-1`と`demo-user-2`の固定ユーザーを使用する。
- ユーザーテーブルは作成せず、予約データの`user_id`に識別子を保存する。
- ServiceはユーザーIDの取得方法に依存せず、渡された識別子を利用する。
- 仮ユーザー識別はローカルプロファイルでのみ有効とする。

## 理由

- **Cognitoの先行導入**：本番相当の認証を実現できるが、Phase 1の開発範囲が拡大する。
- **固定ユーザーのみ**：実装は単純だが、ユーザーごとの予約状態や所有者判定を検証できない。
- **ヘッダーによる仮ユーザー識別（採用）**：認証実装を後回しにしながら、複数ユーザーの操作を検証できる。

## 影響・今後の拡張

- 仮ユーザー識別は認証機能ではないため、外部公開環境では使用しない。
- Phase 3でCognitoのJWTから`sub`を取得する方式へ置き換える。
- ユーザー固有の情報を永続化する要件が生じた場合に、ユーザーテーブルの追加を検討する。
